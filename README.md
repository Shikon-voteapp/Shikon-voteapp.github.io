# 紫紺祭投票アプリ

紫紺祭の投票システムを提供するFlutter Webアプリケーションです。

## バージョン管理

このプロジェクトでは、PowerShellスクリプトを使用してバージョン管理を自動化しています。

### 使用方法

#### 1. 対話型ビルド（推奨）
```powershell
.\build.ps1
```
このスクリプトを実行すると、以下のオプションから選択できます：
- **1**: Patch version (1.0.0 → 1.0.1) - バグ修正
- **2**: Minor version (1.0.0 → 1.1.0) - 新機能追加
- **3**: Major version (1.0.0 → 2.0.0) - 大きな変更
- **4**: Build number only (1.0.0.1 → 1.0.0.2) - ビルド番号のみ
- **5**: Skip version update - バージョン更新をスキップ

#### 2. 自動ビルド
```powershell
.\build-auto.ps1
```
このスクリプトは自動的にビルド番号を増やします（1.0.0.1 → 1.0.0.2）。

### バージョン番号の形式

- **pubspec.yaml**: `Major.Minor.Patch.Build`
  - Major: 大きな変更（互換性のない変更）
  - Minor: 新機能追加（後方互換性あり）
  - Patch: バグ修正
  - Build: ビルド番号

- **アプリ内表示**: `Major.Minor.Patch.Build-Year`
  - Year: 西暦4桁（例：2025）

**例**: 
- pubspec.yaml: `1.0.0.105`
- アプリ内表示: `1.0.0.105-2025`

### 自動更新されるファイル

1. **pubspec.yaml**: バージョン番号
2. **lib/config/vote_options.dart**: データ更新日時
3. **version_config.json**: バージョン設定（自動生成）

### メジャーバージョン更新時の対応

メジャーバージョンを更新する場合（例：1.0.0 → 2.0.0）：

1. `build.ps1`を実行
2. オプション「3」を選択
3. 必要に応じて以下の作業を行う：
   - データベーススキーマの更新
   - APIエンドポイントの変更
   - 設定ファイルの更新
   - ドキュメントの更新

### 注意事項

- バージョン設定ファイル（`version_config.json`）は自動的に作成されます
- コミットメッセージには自動的にバージョン番号が含まれます
- データ更新日時は自動的に現在の日時に更新されます

## 修正内容

### 1. 問題の原因
Flutterの`pubspec.yaml`では、バージョン番号にハイフン（`-`）を含めることができません。これがビルドエラーの原因でした。

### 2. 解決策
**pubspec.yaml**: 従来の形式（`1.0.0.105`）を使用
**アプリ内表示**: 西暦を追加した形式（`1.0.0.105-2025`）で表示

### 3. 修正されたファイル

**`build.ps1`と`build-auto.ps1`**:
- `pubspec.yaml`のバージョン更新時に西暦を追加しない
- 有効なFlutterバージョン形式のみを使用

**`lib/utils/version_info.dart`**:
- `pubspec.yaml`の読み取り時にハイフン形式を期待しない
- `fullVersion`プロパティで西暦を動的に追加
- デフォルト値を適切に設定

**`README.md`**:
- 実際の動作を正確に反映
- pubspec.yamlとアプリ内表示の違いを明確化

### 4. 動作例

**ビルド時**:
```
<code_block_to_apply_changes_from>
```

**アプリ内表示**:
- バージョン情報: `1.0.0.105-2025`

これで、Flutterの制約に従いながら、アプリ内では西暦を含むバージョン表示が可能になりました。
